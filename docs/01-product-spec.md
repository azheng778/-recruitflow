# RecruitFlow 产品规格

## 1. 背景与问题

HR 当前以企业微信、企业微信群和腾讯在线文档为主要工作载体。招聘进展散落在消息和人工表格中，存在以下问题：

- 同一招聘信息需要多次复制、整理和录入；
- 候选人阶段、面试反馈和待办容易遗漏；
- 表格更新滞后，管理者无法看到实时招聘漏斗；
- AI 或人工修改缺少完整审计，错误难以追溯；
- 候选人应聘多个岗位时，单一“候选人状态”无法准确表达流程。

## 2. 产品目标与成功指标

MVP 目标是证明 AI 能把非结构化招聘信息安全地转换为可追踪的业务数据，并形成可演示的完整闭环。

| 指标 | MVP 验收目标 |
|---|---|
| 预置消息结构化准确率 | 关键字段准确率不低于 90% |
| 重复消息/简历 | 100% 不产生重复业务记录 |
| 高风险动作审批覆盖 | 100% 进入审批，不直接执行 |
| 审计覆盖 | 所有状态修改、审批和软删除均可追溯 |
| Dashboard 更新 | 业务提交成功后 2 秒内可见最新统计 |
| 演示可用性 | 无企业微信、腾讯文档凭证时可完整运行 |
| 效率目标 | 典型进展记录操作相对手工录表减少 70% 以上步骤 |

效率目标是产品验证目标，不作为未经实际业务测量的已实现收益对外宣称。

## 3. 用户角色与权限

### 3.1 Admin

- 查看全部岗位、候选人、面试、审批、审计和看板；
- 创建、编辑和关闭岗位；
- 审批所有高风险动作；
- 查看第三方适配器健康状态和重试同步任务；
- 可以恢复已软删除候选人；
- MVP 不提供可视化用户增删改页面。

### 3.2 HR

- 管理候选人、简历、应聘关系和面试；
- 使用 Agent 查询或发起业务操作；
- 审批自己权限范围内的状态变化；
- 查看招聘看板和同步状态；
- 不得恢复软删除记录或查看系统配置密钥。

### 3.3 Interviewer

- 只查看分配给自己的面试与候选人必要信息；
- 填写和修改面试反馈，面试结束后 24 小时内允许修改；
- 不得浏览完整候选人库、修改招聘阶段或审批动作；
- 联系方式默认脱敏。

## 4. MVP 业务范围

### 4.1 必须完成

- 预置账号登录和角色权限；
- 岗位创建、编辑、查看和关闭；
- 文本型 PDF、DOCX 简历上传与 AI 解析；
- 解析结果人工校对后保存；
- 候选人列表、详情和多岗位应聘关系；
- 面试安排、反馈、AI 总结和提醒；
- 招聘阶段状态机与风险分级审批；
- Agent 自然语言查询与白名单工具调用；
- 企业微信群消息模拟、去重、提取和业务更新；
- 本地 Excel 同步与腾讯文档适配器边界；
- 招聘漏斗、岗位进度、来源、转化和待办看板；
- 操作审计、失败重试和敏感信息脱敏。

### 4.2 明确不做

- 普通微信消息抓取或绕过企业微信官方权限；
- 未获得管理员授权时的真实企业微信群全量读取；
- 扫描版 PDF、图片简历 OCR；
- 自动爬取招聘网站简历；
- 用户注册、找回密码和复杂组织权限；
- 正式 Offer 文件签署、薪资审批、电子合同；
- 短信、邮件等收费渠道真实发送；
- 多租户、Redis、Celery、Kubernetes 和微服务拆分；
- AI 自动执行高风险终态操作。

## 5. 核心业务流程

### 5.1 简历入库

1. HR 选择岗位并上传 PDF 或 DOCX。
2. 系统校验扩展名、MIME、大小和 SHA-256。
3. 重复文件返回已存在记录，不重复解析。
4. 系统提取文本；无可提取文本时标记为扫描件不支持。
5. AI 输出结构化候选人信息和解析置信度。
6. 页面展示可编辑预览，HR 确认后创建/匹配候选人。
7. 创建 `candidate_jobs`，初始阶段为 `new`。
8. 写入审计和文档同步任务。

解析失败时保留简历记录和错误原因，不创建不完整候选人。

### 5.2 候选人管理

- 候选人列表支持姓名、技能、来源、岗位、阶段、负责人筛选。
- 同一个候选人可以关联多个岗位，各岗位阶段相互独立。
- 默认以手机号或邮箱精确匹配；无联系方式时不自动合并同名人员。
- 候选人详情展示基础信息、简历、应聘关系、面试、沟通、审批和状态时间线。
- 删除请求进入审批；批准后设置 `deleted_at`，默认查询不再返回。

### 5.3 面试与状态推进

1. HR 为某条应聘关系创建面试并指定面试官。
2. 系统创建面试前 24 小时提醒；不足 24 小时则创建即时待办。
3. 面试官填写优点、不足、反馈和建议。
4. AI 生成摘要，但不覆盖原始反馈。
5. 常规推进在置信度不低于 0.85、匹配唯一且状态合法时自动执行。
6. 高风险或异常情况创建审批请求。
7. 执行结果写入状态历史、审计和同步任务。

### 5.4 群消息自动记录

1. HR 在消息模拟器输入或提交预置群聊消息。
2. 系统根据 `source + external_event_id` 去重。
3. AI 判断消息是否属于招聘业务并提取候选人、岗位、阶段、时间和下一步。
4. 系统匹配候选人与应聘关系。
5. 无歧义常规操作自动执行；其余进入审批。
6. 页面展示原文、提取结果、工具调用名称和最终状态。
7. 同步任务成功后 Dashboard 更新。

无关消息标记为 `ignored`，不创建业务数据；处理失败可重试，但不得重复产生副作用。

### 5.5 Agent 查询与操作

- 查询类问题直接调用只读工具，例如“本周有哪些 Python 岗位候选人要面试”。
- 创建类操作先校验字段和权限，再调用相应工具。
- 修改类操作统一经过风险校验；Agent 不生成或执行原始 SQL。
- 回复展示结果摘要、结构化数据和使用的工具名，不展示思维链。
- 查询默认最多返回 20 条，联系方式脱敏。

### 5.6 审批

1. 系统写入待审批动作、原因、提议数据和业务对象版本。
2. 有权限的 HR/Admin 查看审批卡片。
3. 批准时重新校验当前数据版本和状态机。
4. 校验通过后单次执行并写审计；重复批准返回原结果。
5. 数据已变化时标记冲突，要求重新发起审批。
6. 拒绝只更新审批状态，不修改目标业务数据。

## 6. 页面规格

| 页面 | 核心内容 | 必备状态 |
|---|---|---|
| 登录 | 用户名、密码、演示账号提示 | 错误、锁定、登录中 |
| Dashboard | 漏斗、岗位进度、来源、转化、逾期待办 | 加载、空数据、筛选、刷新失败 |
| 岗位 | 列表、创建、编辑、关闭 | 空数据、表单校验、冲突 |
| 候选人 | 筛选、分页、导入入口 | 加载、空数据、错误 |
| 候选人详情 | 档案、应聘、简历、面试、时间线 | 脱敏、软删除、无权限 |
| 简历导入 | 上传、岗位选择、解析预览、人工校对 | 上传、解析中、失败、重复 |
| 面试 | 日程列表、创建、反馈、状态 | 角色限制、逾期提醒 |
| 审批中心 | 待办、已处理、批准、拒绝、冲突 | 重复操作、版本冲突 |
| Agent 工作台 | 会话、快捷问题、结果表、审批卡片 | 流式等待、工具错误、降级 |
| 消息与同步 | 消息模拟器、事件轨迹、同步任务 | 去重、忽略、失败、重试 |

所有修改表单必须有确认结果；错误必须提供可执行的下一步，不允许只显示“系统错误”。

## 7. 业务规则

- 关闭岗位后不能新增应聘关系或面试，已有历史可查看。
- 面试必须关联一条有效应聘关系。
- Offer、入职、淘汰、放弃均属于高风险状态。
- `hired`、`rejected`、`withdrawn` 为终态；恢复需 Admin 发起新的审批。
- 联系方式在列表、Agent 回复、面试官页面和日志中脱敏。
- 原始简历文本和面试反馈不能被 AI 摘要覆盖。
- 时间统一以 UTC 存储，接口使用 ISO 8601，页面按 `Asia/Shanghai` 展示。
- Demo 数据必须为虚构数据，姓名和联系方式不得映射真实个人。

## 8. 演示主线

1. 使用 HR 演示账号登录并查看初始漏斗。
2. 上传一份 PDF 简历，校对解析结果并绑定岗位。
3. 通过模拟器发送“一面通过并安排二面”的消息。
4. 展示 Agent 提取、候选人匹配、自动阶段推进和审计记录。
5. 发送一条淘汰消息，展示高风险审批而不是直接修改。
6. 批准审批，查看状态历史、Excel 同步任务和 Dashboard 变化。
7. 向 Agent 提问“本周还有哪些候选人要跟进”。
