## 1. 文档目的

本文档是 RecruitFlow 的开发规格入口。它用于让开发者或编码 Agent 在不重新询问业务规则的情况下，按照固定顺序完成开发、测试和交付。

实现与本文档冲突时，以本目录中的规格为准；原始讨论文件仅作为背景材料，不作为最终接口或数据结构的直接依据。

## 3. 项目定义

RecruitFlow 是面向 HR 的 AI 招聘协作平台。平台把简历、候选人、岗位、面试、群聊进展、审批、提醒和招聘指标统一到一条可追溯的数据链路中。

MVP 必须完整演示：

```text
群消息或简历输入
  → AI 结构化提取
  → 候选人与岗位匹配
  → 风险校验
  → 自动更新或人工审批
  → 审计记录
  → 文档同步任务
  → 看板实时反映结果
```

## 4. 已锁定决策

| 编号 | 决策 | 结论 |
|---|---|---|
| D-001 | 产品范围 | 完整招聘管理平台 MVP，而非单一解析器或聊天机器人 |
| D-002 | 业务数据库 | 使用本机 MySQL 8，新建 `hr_recruitment`；禁止修改 `langchain_db` |
| D-003 | 前端 | FastAPI + Jinja2 + HTMX/原生 JavaScript + ECharts |
| D-004 | 登录 | 预置 `admin`、`hr`、`interviewer`，不开放注册 |
| D-005 | 简历 | 支持文本型 PDF、DOCX；扫描件明确提示不支持 |
| D-006 | 招聘阶段 | 阶段以 `candidate_jobs` 为唯一可信来源，不放在候选人主表 |
| D-007 | AI 审批 | 置信度阈值为 `0.85`；高风险动作无条件审批 |
| D-008 | 外部系统 | 默认使用消息模拟器和本地 Excel；真实适配器可配置、可 Mock |
| D-009 | 删除 | 候选人只允许审批后的软删除，不提供硬删除 API |
| D-010 | 模型 | 通过 OpenAI-compatible 接口调用 Qwen，配置名统一为 `LLM_*` |
| D-011 | 标识符 | 主业务实体用 UUID；事件、日志类表用自增 BIGINT |
| D-012 | 展示边界 | 展示工具名、参数摘要和执行结果，不展示模型内部思维链 |

## 5. 规格优先级

发生不一致时按以下优先级处理：

1. `docs/DEV_SPEC.md` 中的锁定决策；
2. `docs/appendices/` 中的字段与接口契约；
3. 产品规格中的业务规则；
4. 技术规格中的实现原则；
5. 原始讨论材料。

不能由优先级消解的冲突必须暂停相关模块，新增决策记录后再继续。不得由实现者自行扩大业务范围。

## 6. 术语表

| 术语 | 定义 |
|---|---|
| 候选人 Candidate | 自然人基础档案，与具体应聘岗位分离 |
| 应聘关系 Application | `candidate_jobs` 记录，即候选人应聘某一个岗位的流程实例 |
| 招聘阶段 Stage | Application 当前所处阶段 |
| 常规推进 | 非终态、非敏感且符合状态机顺序的阶段变化 |
| 高风险动作 | Offer、入职、淘汰、放弃、删除、批量修改等动作 |
| 审批 Approval | AI 提议后由有权限的 HR 或管理员批准或拒绝 |
| 入站事件 Inbound Event | 来自模拟器或企业微信的原始消息及其处理状态 |
| 文档同步任务 Sync Job | 将招聘数据写入 Excel 或腾讯文档的可重试任务 |
| Agent Tool | Agent 可调用的白名单业务能力，不接受原始 SQL |
| Checkpointer | 保存 LangGraph 中断状态、支持审批后恢复的持久化组件 |

## 7. 需求变更流程

任何影响数据库、接口、角色权限、状态机、审批边界或验收口径的变更，必须按以下步骤执行：

1. 在本文档“决策记录”中新增编号、背景、结论和影响范围。
2. 同步更新产品或技术规格。
3. 同步更新数据库/API 附录。
4. 更新验收矩阵并补充回归用例。
5. 最后修改代码和迁移。

文案、样式或不改变行为的内部重构不需要新增决策，但仍须通过已有测试。

## 8. 开发门禁

进入编码前必须满足：

- 当前阶段的输入、接口和验收项已明确；
- 不需要新业务决策；
- 数据库迁移可以在全新 `hr_recruitment` 上执行；
- 测试不得指向 `langchain_db`；
- `.env` 已被忽略，代码和文档不包含真实密钥。

模块完成的统一定义：

- 正常与异常路径均实现；
- API 契约、权限和审计符合规格；
- 自动测试通过；
- 页面包含加载、空数据、成功和失败状态；
- 不产生未记录的数据库副作用；
- 对应验收矩阵已标记并保留证据。
